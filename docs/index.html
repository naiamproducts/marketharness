MarketHarness

MarketHarness puts a full marketing team in your terminal — evidence-backed audience research, content drafts, and publishing that only happens with your approval.

GitHub repo Quick start
OpenCode V1 distribution 5 agents 8 skills 6 slash commands confirm-bound publishing optional Qloo MCP

//Problem → solution

Fragmented context → generic, risky content

  • Research, drafts and publishing live in three different tools — nothing carries over.
  • Claims come from vibes, with no source and no separation of fact from guess.
  • Anyone (or any agent) can hit post; a typo becomes public in one keystroke.

Structured workspace + evidence + confirm-bound publishing

  • One workspace per company/project: brand, policies, knowledge, deliverables as files.
  • Every research output is labeled EVIDENCE / INTERPRETATION / HYPOTHESIS with citations.
  • Publishing needs your explicit, payload-bound approval — and every action is logged.

//How it works

1

Brief

Drop an objective. /marketharness-brief turns it into goal, context, audience and success criteria.

2

Lead delegates

The Marketing Lead routes the brief to research, growth and community — and to the audience-researcher subagent for Qloo-backed questions.

3

Research with citations

Findings land as EVIDENCE (tool, query, status), INTERPRETATION and HYPOTHESIS — kept apart, never blended.

4

You review, then publish

Deliverables are drafts. /marketharness-publish prepares an immutable payload; you confirm the exact text; the connector executes and appends to the action log. Replays are refused as duplicates.

//The team

AgentRole
marketing-leadprimary · default Receives briefs, delegates to research/growth/community, consolidates deliverables. Never does deep research or drafting itself.
researchprimary Direct audience research: discovery, synthesis, evidence-backed findings. Invokes the audience-researcher for Qloo-backed queries. Never publishes.
growthprimary Positioning and experiments: messaging pillars, tests with pre-registered thresholds, verdicts on results. Drafts only, never publishes.
communityprimary Posts, replies and comment triage. Drafts only — publishing always goes through the connector prepare + confirm flow.
audience-researchersubagent Qloo-backed audience specialist, invocable by marketing-lead and research. Same evidence criteria as direct use; never publishes.

Qloo — audience evidence, not API trivia

The audience-researcher subagent talks to Qloo's cultural data through the official MCP harness ({"command":"qloo","args":["mcp"]}). Results arrive as EVIDENCE with a provenance block — tool, query, status, result count, source and limits — and stay separate from our own INTERPRETATION. No credential is ever written to a config file; without the CLI or a key, the agents state "no Qloo research performed".

Safe use: aggregate affinities only, with source and limits shown — no inference about an individual, no causal claims, no personal data sent to Qloo, and a human confirms material entity/tag choices. See the official Qloo Hackathon Kit.

//Safety

Confirm-bound publishing

execute accepts only the token minted for the exact payload you approved — account, project, full text, attachments, target.

Payload-bound tokens

Edit one character and the approval is stale (confirm_stale): you re-approve the new payload, never the old one.

Dedup action log

Every execution appends to an append-only log; re-running the same action_id is refused with the prior external_id — no blind retries.

Permissions are config, not prompts

delete: deny, rm -rf *, sudo *, git push * and the publish ask rule live in the shared profile config — agent prompts only restate them.

Fully isolated install

Own pinned runtime, own XDG dirs, own rendered config: marketharness never reads or writes your existing OpenCode setup, credentials or sessions.

//Quick start

git clone https://github.com/naiamproducts/marketharness.git
cd marketharness
./install.sh        # preflight -> pinned runtime -> rendered config -> CLI link
marketharness       # first launch prints the onboarding checklist

# optional Qloo enablement — the harness is installed by you, never by us
npm install --global @qloo/qloo-harness   # Node >= 22.19
qloo setup --qloo                        # event key -> harness private config
marketharness --stage-only                # re-render: mcp.qloo appears

Then inside the TUI run /marketharness-init (workspace → company → project → model → optional Qloo → optional social → first brief). Full setup, checklist and known limitations are in the README.
